Layered Architecture

1 Ingestion Layer

open-wa (wa-automate) delivers inbound messages to a single FastAPI webhook. Two WhatsApp numbers run as two sessions — one for citizens, one for officers — and the router decides the path by the recipient number. Privacy-masked senders (@lid) are auto-resolved to real numbers via the contacts API; photos arrive as inline base64 and are decoded to bytes; an anti-loop guard ignores the platform's own numbers. Per-channel conversation history is buffered in Redis to disambiguate short replies.

2 Understanding Layer

A chain of specialized LLM agents turns free text + photos into structured data: intent classification (report vs. complaint vs. query vs. generate-report), field extraction, geocoding of location text, image captioning with claim-matching, and complaint category / sentiment / safety classification. Each agent runs on the model best suited to its task, with an automatic OpenAI ↔ local-vLLM fallback chain.

3 Reality Layer

Complaint text is embedded (Qwen3 embeddings) and clustered into issues in a Qdrant vector store. A deterministic scoring engine then computes urgency, activity quality, correlation, operational-gap, conflict, and an overall Reality Alignment Index — all by fixed, auditable formulas (the AI only extracts indicators, it never invents the score). Gaps and conflicts trigger disposition recommendations.

4 Presentation Layer

A FastAPI API serves a React 19 command dashboard. Live arrivals are pushed over WebSocket with an HTTP-polling fallback, rendered as click-to-fly map notifications. An SSE-streamed AI assistant lets executives "talk to the data" across both complaints and reports. Two PostgreSQL databases (operational + reality) are merged at the API layer.

Engineering Challenges Solved

1 Two Voices, Two Databases

Operational data (officers, reports) lives in one PostgreSQL DB; reality data (complaints, issues, scores) in another. They cannot be joined in a single query, so cross-database views (e.g. the unified photo gallery) are merged and re-sorted at the API layer.

2 WhatsApp Privacy (@lid)

WhatsApp may mask a sender as an @lid identity instead of a phone number, which broke officer recognition. The system resolves the real number through open-wa's contacts API and caches the alias so a registered officer is never mistaken for a stranger.

3 Photos Arrive as Base64

open-wa delivers images inline as data:image/jpeg;base64,… — not URLs. The parser detects media, wraps it as a data-URL, and a single decode path stores it to object storage so vision analysis runs identically for complaints and reports.

4 Auditable, Not Hallucinated Scores

Decision-makers need numbers they can defend. The LLM only extracts indicators (safety signal, sentiment, evidence quality); every score is then computed by a fixed weighted formula, so the same inputs always produce the same, explainable result.

5 Conversational Memory

Replies like "yes", "this week", or "2" are meaningless without context. A per-channel Redis buffer (TTL-bounded) feeds the last few turns into the intent classifier so the bot understands follow-ups across complaint, report, and chat channels.

6 Real-time Without Reliable WebSocket

Behind some proxies the dashboard WebSocket upgrade fails. A 12-second HTTP-polling fallback fetches recent complaints and reports, de-duplicates, and fires the same click-to-fly notifications — so live alerts keep working regardless of the transport.

Pipeline
How a Message Becomes a Scored, Routable Signal
Two end-to-end pipelines run on the same intake. Complaints flow toward clustered issues and disposition; reports flow toward validation and correlation. Most stages are feature-flagged and run asynchronously.

● Complaint Pipeline (Voice of the Public)

1

Intake

A citizen messages the complaint number. The service de-duplicates by message id, applies an anti-spam guard (rate-limit + cooldown), and walks a small state machine — asking for a location only when the text doesn't already contain one.

2

Geocode

The location agent normalizes the place text and the Nominatim client resolves it to coordinates + administrative area (province / city / district / sub-district). Shared GPS is used directly when present.

3

Vision

Attached photos are stored and analyzed: a caption is generated and matched against the complaint text (0–1), with location cues extracted from the image when possible.

4

Classify

A classifier assigns category, sentiment, and safety threat. Below a confidence threshold the complaint is sent to an operator review queue with an SLA instead of being auto-trusted.

5

Embed & Cluster

The text is embedded and searched against the Qdrant vector store. Within a geo + time gate, a similarity ≥ 0.50 joins the complaint to an existing issue; otherwise a new issue is created (≥ 0.65 flags a likely duplicate).

6

Score

Deterministic engines compute complaint urgency, then issue-level Operational Gap (OGS), Problem Conflict (PCS), and the overall Reality Alignment Index (RAI) on a scheduled sweep.

7

Disposition

When an issue crosses the gap or conflict threshold, the recommendation engine builds a disposition. High-confidence recommendations support one-click approval; lower-confidence ones require validation.

Feature flags (intake, classification, clustering, scoring, disposition) let each stage be enabled independently, and most run as fire-and-forget async tasks plus a scheduled sweep — so a slow vision call or LLM timeout never blocks message acknowledgement.

Integrations
WhatsApp-native by Design
No app to install, no form to fill — the entire intake surface is WhatsApp via open-wa (wa-automate). Around it sit geocoding and object storage to turn raw messages into mapped, evidenced records.

1 Two Numbers, Two Sessions

open-wa runs two WhatsApp sessions — a system number for officers and a complaint number for citizens — both pointing at one webhook. Inbound is routed by the recipient number, and outbound replies are sent back through the matching session so each side always hears from the right number.

system → +62 819 9967 9588 (officer reports) complaint → +62 878 1196 2146 (citizen aduan)

2 Inbound Webhook

A single POST /webhook accepts the open-wa v5 envelope, optionally verifies a shared secret, returns 200 immediately, and processes the message on a background task — so WhatsApp is never kept waiting.

3 @lid Privacy Resolution

When WhatsApp hides a sender behind an @lid identity, the system calls the contacts API to recover the real number and caches it as an alias — so a registered officer is recognized even when their number is masked.

4 Inline Base64 Photos

Images arrive embedded as base64, not links. The parser wraps them as data-URLs and a unified decode path stores them to object storage, so the same vision pipeline runs for both complaints and reports.

5 Anti-Loop Guard

Because the platform owns two numbers that can message each other, every inbound is checked against both system numbers and dropped if it originates from one — preventing an infinite bot-to-bot reply loop.

6 Per-Channel Memory

A Redis buffer keyed by wa:ctx:{channel}:{phone} keeps the last few turns (TTL-bounded) for the complaint, report, and chat channels — giving the intent classifier the context to understand follow-ups and one-word replies.
