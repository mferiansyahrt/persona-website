Dari Excel KONIS ke Live Dashboard
Data sumber adalah formulir KONIS PBS-321 (kondisi sistem kapal milik TNI AL). Diparse offline dari Excel, di-clean ke TypeScript untuk dashboard front-end, dan di-loaded ke SQLite untuk akses AI assistant. Single source of truth di repo, tanpa external database query saat dev mode.

Dual Data Path — Sama Source, Beda Format

1

Excel KONIS PBS-321 (Source of Truth)

Formulir resmi TNI AL berisi 488 komponen KRI Brawijaya-320 dengan field: kode, nama, segmen (A Platform / B SEWACO / C Logistik), KONIS (Siap/Tidak Siap), kondisi %, prioritas P1-P4, dampak misi, uraian kerusakan, target penanganan. Plus sheet untuk amunisi, LOGCA (BBM/oli/air), klaim vendor.

2A

Path A — Frontend Mock TypeScript

Script parse-excel.mjs mengubah Excel ke src/data/mock-*.ts (9 files). Setiap file export const seperti MOCK_KOMPONEN, MOCK_AMUNISI, dst. dengan TypeScript interface ketat. Direct import via custom hooks — instant load, no API, no loading state.

2B

Path B — Backend SQLite ETL

Script build_sqlite.mjs (Node + better-sqlite3) generate data/argus.db dari source Excel yang sama. Schema 11 tabel + indeks pada segmen/prioritas/konis. SQLite ini eksklusif untuk AI assistant tool calling — dashboard FE tidak baca DB ini. Pemisahan ini menjamin konsistensi data: AI dan dashboard melihat angka identik karena berasal dari sheet yang sama.

3

Synchronization Guarantee

Karena AI dan FE menggunakan source yang identik (Excel), kalau user tanya AI "berapa komponen P1 di segmen platform?" dan widget Status Sistem menampilkan angka berbeda → bug yang harus diperbaiki. Test smoke verifies dua angka match untuk top-N field kritikal.

Data Challenges Solved

1 Excel Field Inconsistency

Banyak field di KONIS yang bernilai placeholder (kondisi 100% default parsing, jam_pakai NULL, uraian_kerusakan NULL untuk komponen P3/P4). System prompt secara eksplisit memberitahu AI: "kondisi 100% bukan berarti komponen riil 100%, itu default parsing".

2 Multi-Schema Cross-Reference

Amunisi terpisah dari komponen, tapi launcher (komponen segmen B/SEWACO) butuh referensi amunisi yang dipakai. Tool gap_amunisi_per_sistem melakukan cross-join SQLite supaya AI bisa surface "Aster 15/30 launcher OK tapi amunisi 0 stok".

3 FFBNW Surfacing

5 amunisi strategis status FFBNW (Fitted For But Not With) — launcher terpasang, amunisi 0. Karakteristik unik PPA-class. Modul Analisis Tempur menampilkan ini sebagai capability gap utama yang menjelaskan kenapa TC (~98%) berbeda jauh dari CRS (~58%).

4 Enum Hallucination Prevention

LLM cenderung lowercase enum value (mis. "available" untuk amunisi). Tools menggunakan Pydantic BeforeValidator dengan synonym map ("available" → "AMAN") plus prompt eksplisit dengan daftar enum value WAJIB UPPERCASE Indonesia.

5 Derived Metrics Real-Time

TC, CRS, Overall Readiness, dan health per segmen tidak disimpan di SQLite — di-compute on-fly oleh tools (compute_overall_readiness, analyze_segment_health). Memastikan AI selalu compute dari raw data dan tidak terpancing untuk reasoning dari memory.

6 Per-Page Tool Scoping

Tanpa scoping, mode SPECIFIC akan call semua 19 tools yang membingungkan. PAGE_TOOLS_MAP backend menyimpan whitelist tools per page slug (mis. logistik scope ke query_amunisi, query_logca, ffbnw_gap_analysis). Tools yang relevan di-inject ke system prompt.

ARGUS AI
Talk to Your Ship Data
AI assistant terintegrasi sebagai global drawer yang dapat diakses di setiap halaman. Tiga mode operasi yang menentukan scope tools yang dipakai LLM. SSE streaming dengan tool call visualization real-time supaya user paham AI sedang query data apa.

Three Operating Modes

INTERNAL Default Q&A

Akses penuh ke 19 internal tools SQLite. Untuk pertanyaan umum tentang kapal — kondisi komponen, status amunisi, klaim vendor, readiness scoring.

  • System prompt: argus_system_internal.txt
  • Scope: semua tools internal (19)
  • Example: "Berapa komponen P1 di SEWACO yang TS?"

SPECIFIC Page Context

Mode otomatis aktif saat user buka drawer di halaman tertentu. AI di-scope ke subset tools yang relevan untuk page itu, dan prompt menginjeksikan label page + daftar tools.

  • System prompt: argus_system_specific.txt (template)
  • PAGE_TOOLS_MAP di backend: 8 slug → tool subset
  • Example di /logistik: "Berapa hari operasi dengan stok BBM saat ini?"

GENERAL OSINT Analysis

Mode geopolitical/contextual analysis. AI pakai web search (Brave Search → SerpAPI fallback) untuk OSINT, BUKAN data KONIS internal. Untuk analisis perbandingan kapal regional, situasi maritim.

  • System prompt: argus_system_general.txt
  • Scope: brave_search_single, fetch_url_content
  • Example: "Bandingkan PPA-class dengan korvet ASEAN"

Triple-Provider LLM Fallback

Untuk resilience, ArgusAgent membungkus 3 LLM provider dalam chain. Kalau provider pertama gagal (rate limit, quota, atau API error), agent otomatis rebuild dengan provider berikutnya dan retry stream dari awal. Frontend menerima provider_used di event done.

# .env config LLM_PROVIDER_CHAIN=openai,openrouter,vllm_local OPENAI_MODEL_CHAT=gpt-4o-mini OPENROUTER_MODEL_CHAT=meta-llama/llama-3.3-70b-instruct VLLM_BASE_URL=http://localhost:8000/v1 VLLM_MODEL=gpt-oss-20b

SSE Heartbeat (Multiplex Queue)

Mode GENERAL bisa idle 30-60 detik selama tool calling (web search + URL fetch). Tanpa heartbeat, koneksi SSE bisa terputus di reverse proxy (nginx 60s default, Cloudflare 100s hardcoded). chat.py menggunakan asyncio.Queue multiplex pattern dengan dua task: main_stream push event chat, heartbeat push : ping\n\n tiap 15 detik. Browser SSE parser ignore comment lines, koneksi tetap aktif.

Per-Mode + Per-Page Session Isolation

Redis key: argus:chat:session:{session_id}:{mode}[:{page}]. Untuk satu user session ID, mode INTERNAL/GENERAL/SPECIFIC × halaman aktif memiliki riwayat chat terpisah. Switch mode atau navigate antar page tidak mencampur context — masing-masing fresh dengan history sendiri. TTL 1 jam, max 20 messages per key.

Build & Deploy
Vite Production Pipeline
Frontend di-build sebagai static SPA, backend FastAPI sebagai service uvicorn terpisah. Deployment minimal: reverse proxy nginx/caddy meneruskan request ke Vite preview server (port 16327) dan FastAPI (port 8011) di mesin yang sama. Tidak ada Docker / CI di repo — tmux + manual rebuild flow.

Dev Mode vs Preview Mode

pnpm dev Development

Vite dev server dengan HMR — file watch + WebSocket push untuk auto-reload browser saat source edit. Optimal untuk development. Cocok juga kalau mau live update di domain via reverse proxy (selama proxy support WS upgrade header).

  • Port 16327, host 0.0.0.0, strictPort
  • HMR socket via /__vite_ping
  • Proxy /api/* → localhost:8011
  • Source TypeScript on-the-fly compiled

pnpm build + preview Production

tsc -b (TypeScript check incremental) + vite build → minified bundle ke dist/. Lalu vite preview serve static files. Tidak ada HMR — perubahan source TIDAK propagate ke browser sampai rebuild. Optimal untuk demo stabil.

  • Bundle main ~432 KB, gzipped ~134 KB
  • Per-page lazy chunks 18-40 KB each
  • Build time ~25-30 detik
  • preview block di vite.config.ts mirror server block

Design Decisions Worth Noting

A Mock TypeScript Over Backend API for Dashboard

Untuk PoC scope, dashboard tidak perlu real-time DB query. Mock .ts files lebih cepat dimuat, mudah di-edit oleh designer, dan menghilangkan backend dependency untuk demo statis. Backend cuma untuk AI assistant.

B Iframe for 3D Instead of React-Three-Fiber

Vanilla HTML + Three.js terisolasi lebih ringan dari R3F. Tidak ada React re-render overhead. Iframe juga membuat 3D module portable — bisa di-embed di project lain tanpa membawa React tree.

C Adaptive Typography via CSS clamp() + User Zoom

Tokens --fs-N di theme.css: calc(clamp(min, vw-based, max) * var(--user-zoom)). Auto-scale dengan viewport, plus user-control via TopBar +/- buttons (80-150%, step 10%). Iframe sync via postMessage.

D Briefing as Hybrid TS + Markdown

Structural data (header, badges, stages, capabilities) di TypeScript dengan strict typing. Prose content (paragraphs "What This Module Does") di markdown — easier to edit, rendered with react-markdown. Vite raw glob import untuk loading dynamically.

E Disclaimer-First UX di Fault Reports

Dashboard militer: konten prediktif harus selalu di-frame sebagai prediksi/ilustrasi. Banner kuning prominent di TOP, kata "PREDIKSI" + "TIDAK menyatakan kondisi aktual" eksplisit. Mencegah salah interpretasi oleh non-teknis viewer.

F No Auth (Yet)

PoC scope: deploy ke domain semi-public dengan content UNCLASSIFIED. Tidak ada login flow. Untuk production deployment, perlu tambah authentication (mis. SSO Kemhan, JWT) di reverse proxy layer + backend middleware.
