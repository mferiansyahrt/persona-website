Layered Architecture

1 External Data Sources

Each social media platform provides data through third-party APIs (RapidAPI). The system does not directly access the platforms, but instead goes through the RapidAPI gateway which manages authentication, quotas, and rate limits. This means data availability depends on third-party reliability.

2 Internal Wrapper Service

An intermediary service built on internal infrastructure. Each platform has its own endpoints for: searching accounts, fetching detailed profiles, and downloading recent posts. This wrapper standardizes response formats and handles RapidAPI errors before forwarding data to the main application.

3 Normalization & Transformation

Raw data from each platform has vastly different JSON structures. This stage maps all data to a common schema: name, username, bio, location, profile picture, posts, engagement counts, and images. It also extracts email, phone number, and birthdate from bios using pattern matching.

4 Context for AI Agents

Normalized data is combined with Elasticsearch search results (post history) and packaged into structured text. Each post is numbered sequentially with timestamps and image descriptions (from Visual AI analysis). This context becomes the input received by 24 AI agents.

Key Challenges Solved

1 Every Platform Has a Different Format

Instagram, TikTok, Twitter, Facebook, YouTube, and LinkedIn each return completely different JSON structures. Post text alone is stored in 5 different fields depending on the platform. All must be mapped to a single unified schema.

Instagram → caption.text TikTok → post_desc Twitter → full_text YouTube → snippet.title + snippet.description Facebook → (not available)

2 Different Timestamp Formats

Each platform uses a different timestamp format: Instagram uses Unix epoch (seconds since 1970), Twitter uses a custom text format, YouTube uses ISO 8601 UTC, and TikTok is pre-formatted. All must be converted to a single format.

Instagram → 1708976400 (Unix epoch) TikTok → "2024-02-26 10:30:00" (ready to use) Twitter → "Mon Feb 26 10:30:00 +0000 2024" YouTube → "2024-02-26T10:30:00Z" (UTC)

3 Parallel Fetching Across 5 Platforms

All platforms are fetched simultaneously using AsyncIO to minimize wait time. However, this means an error on one platform must not halt the others. The system uses a 3x retry mechanism with 1-second delays between attempts.

4 Images Must Be Analyzed by AI

Every image from posts is downloaded and sent to a Vision Language Model to obtain image content descriptions, identified locations, and visible activities. This process runs in parallel but is prone to failures (deleted images, expired URLs), so it uses 3x retries with exponential backoff.

5 Data from 3 Sources Combined

For each account, data is collected from 3 different sources in parallel: the social media profiling API, RapidAPI wrapper, and Elasticsearch index (history). These three sources sometimes produce overlapping or differing versions of data, and must be merged into a single coherent context for agents.

6 Per-Platform Data Limitations

Facebook does not provide posts, LinkedIn can only be accessed via job search, and some platforms require 2 API calls (search first, then fetch details). The system must handle each limitation gracefully without halting the overall process.

Data Transformation Pipeline

1

Account Search

The system receives a URL or username, then searches for the account across all platforms in parallel. Each platform has its own search endpoint. Search results are matched to find the correct user ID.

2

Normalization to Common Schema

Profile data from each platform is mapped to a uniform format: full name, username, bio, location, profile picture, follower count, verification status, and contact information extracted from bio.

3

Post & Image Retrieval

Recent posts are fetched along with metadata (dates, engagement, images). Each image is downloaded and analyzed by Vision AI to generate visual descriptions. Posts are numbered sequentially and packaged in markdown format.

4

Enrichment from Elasticsearch

Older post history is randomly sampled from the Elasticsearch index, providing richer temporal context. Data from 3 sources (social media API, RapidAPI, and Elasticsearch) is merged into a single context document.

5

Context Assembly for Agents

All data is packaged into structured text that AI can understand: account profile, numbered posts complete with image descriptions, and history. This context is what the 24 AI agents receive to perform deep analysis.

Workflow
From URL to Complete Profile
The entire process runs automatically — just enter a social media account link.
1

Enter Account Link

The user enters one or more social media account URLs to be analyzed. The system supports Instagram, TikTok, X (Twitter), Facebook, YouTube, and LinkedIn.

2

Automatic Data Retrieval

The system fetches profile data, recent posts, and images from each platform in parallel via RapidAPI. Each post image is analyzed by Vision AI to obtain visual content descriptions.

3

24 Agents Analyze Simultaneously

Normalized data is sent to 24 AI agents running concurrently: profile agents extract demographics, scoring agents assess risk and positive potential, criminal agents search for legal records, and visual agents analyze biometrics.

4

Deterministic Scoring

AI extracts indicators from content, then scores are calculated using fixed formulas (not AI) to ensure consistency. Digital Risk Score assesses risk across 6 aspects, Potential Positive Score assesses positive impact across 6 other aspects.

5

Criminal Record Research

Criminal agents autonomously search for news and legal records through Google Search and Brave Search. The agent determines its own search keywords, reads articles, compiles chronologies, and verifies whether the found records belong to the same person.

6

Final Report

All results are combined into a comprehensive profile with an executive summary, risk and positive scores, affiliation analysis, criminal records, and facial biometrics. Exported as a JSON file and 3 PDF reports.
