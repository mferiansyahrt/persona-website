What It Does

From Raw Signals to Action Plans

This engine is not an issue detector — it receives issues already detected by the Cognitive Warfare Engine, then transforms them into concrete response decisions.

📡
Ingest

Every 60 minutes, the scheduler fetches the list of newly-emerged main_issue_ids from the Elasticsearch index cw-campaign-issue-event-monitoring — the output of the Cognitive Warfare Engine.

⚖️
Evaluate

14 AI agents work sequentially & in parallel: refine sentiment from the client's perspective, compute velocity, jurisdiction, monitoring decision, action decision (Normal/Crisis/War), and chronological timeline.

🎯
Respond

When action is required, the system generates reply content recommendations per platform, a precision scoring PDF, and automatically posts to targets via the Campaign API. Results are pushed to 3 Kafka topics.

Three Decision Tiers

Normal · Crisis · War

After full analysis, the engine assigns an urgency level based on velocity, sentiment, weighted triggers, and client sensitivity. Each level triggers a different response.

Normal
Score 0–39
Preventive awareness. Positive/neutral sentiment, low velocity. Routine monitoring every 72 hours over 45 days. No campaign action.
Crisis
Score 40–79
Crisis containment. Negative sentiment, moderate-to-high velocity, triggers ≥3.0. Strategic/selective action every 48–96 hours over 21–30 days.
War
Score 80–100
Narrative domination. Highly negative sentiment (>60%), critical velocity, mission-critical issue. Urgent action every 12 hours over 14 days, auto-post to targets.
How It Works

From Main Issue to Campaign Execution

This pipeline runs for every main_issue_id that passes selection. Each stage has conditional gates — irrelevant issues are skipped early to save LLM resources.

1
Scheduler Selects Active Issues
Every 60 minutes, the scheduler queries Elasticsearch cw-campaign-issue-event-monitoring for main_issue_ids with agent_process_time within the last 1-hour window. Result: unique main_issue_ids per client (max 100).
ES AggregationPer-client filter
2
Fetch All Events for the Issue
Per main_issue_id, fetch all related events (max 30, sorted by agent_process_time desc) — with no time filter. Each event is a variant/case of the same main_issue (e.g., main_issue "MBG Poisoning Crisis" → events in Bandung, Bekasi, Jakarta).
3
Event Deduplication
The dedup agent filters similar events based on WHO-WHAT-WHERE-WHEN, capped at 7 unique events. Done before aggregation to prevent narrative duplication that would skew sentiment.
AI Event Dedup
4
Multi-Event Context Aggregation
Merges all events into a single document: combines issue_platform_mentioned_count with post_url-based dedup, sorts posts by follower desc, takes the top 10 per platform. Descriptions are filtered to the last 7 days only. Lucene queries are joined with OR.
Top 10 per platformDedup by URL
5
Sentiment Refinement from Client Perspective
The sentiment agent maps each event to in-scope / out-of-scope of the client's mandate, then renders an overall verdict: Positive/Negative/Neutral with an alert score 0–100. Polri has a dedicated protocol (self-inflicted, decision tree).
AI SentimentPer-event mandate map
6
Gate: Urgency Filter
The filter agent evaluates whether the issue is threatening enough to the client's reputation to warrant a campaign. Score <70 or verdict false → pipeline stops here (saving dozens of LLM calls). Output is always sent to the Kafka topic cw-campaign-issue-urgency unconditionally.
Gate FilterKafka: urgency
7
Building the Crisis Context
Pulls additional data for full context: NCW summary & lifecycle from an external API, hourly velocity from the cw-data-* index over 3 days, and sentiment distribution from prod-social-media-*.
The following 3 processes run in parallel
Summary Description

Builds an executive summary of the issue plus 5W info (what/who/when/where/why/how) in a dashboard-ready format.

Jurisdiction Extraction

Determines the geographic scope (province, regency, sub-district, village) and confidence level based on event content.

Monitoring Decision

Decides whether the issue needs monitoring, for how long, and at what check interval.

8
Gate: Monitoring Required?
If the monitoring agent returns required=False, the pipeline stops. If True, it proceeds to the action decision — simultaneously refetching the latest posts from prod-social-media-* (12 days) and reranking to obtain relevant sample posts.
Early SkipRefetch + Rerank
9
Action Decision: Normal/Crisis/War
The pipeline core. Computes velocity_impact_score = peak_velocity × sentiment_multiplier, compares it against the client's sensitivity threshold, validates with weighted triggers (CRITICAL=3.0, HIGH=2.5, MEDIUM=1.5), and applies override logic. Outputs a level + score 0–100.
Velocity LogicWeighted TriggersOverride Rules
The following 4 processes run in parallel (when action is required)
Action Detail

Assembles concrete action details: action type, target audience, talking points, duration, and category tags.

Campaign Planner

Produces a complete campaign plan with reasoning, intervention type, and integration with crisis metrics.

Key Profiles Extraction

Identifies originators, amplifiers, tier-1 media outlets, influential accounts, and regular accounts spreading the narrative.

Chronological Timeline

For tag specific: a 3-stage timeline agent (extract → confidence scorer → strict remapper). For generic: per-event timeline in parallel with search tools (Brave Search + Knowledge Repo).

10
Exposure Tracking via Redis
On every run, current exposure (velocity + sentiment metrics) is stored in Redis under a per-(main_issue_id + client) key. The latest exposure (from the previous run) is also retrieved for trend comparison.
Redis CacheTrend Tracking
11
Gate: Action Required & Negative Sentiment & Level War/Crisis
Only when all three conditions are met does the pipeline proceed to post-processing agents 10–11. Otherwise it is just pushed to the Kafka log for audit trail without any concrete action.
12
Platform Post Recommendation
The agent produces reply content recommendations per platform (Twitter, Facebook, IG, TikTok, etc.): posting schedule, posts-per-day, total posts, total comments, reasoning, and image/video metadata.
AI Content Generator
13
Precision Scoring + PDF
The precision agent computes 5 dimensions (legitimacy_impact, persistence_escalation, reach_media, sentiment, velocity_exposure), validates consistency against the target level score, and generates a PDF report uploaded to S3.
5-Dimension ScoringS3 Upload
✓
Execution: Kafka + Campaign API
The final output is published to cw-campaign-main-issue-monitoring-idea (downstream consumer), cw-campaign-main-issue-monitoring-log-idea (audit log), and via the Campaign API for automatic comment/content posting to relevant social media targets.
Kafka: ideaKafka: logCampaign API: commentCampaign API: content

📋 Why 3 Different Scenarios?
Mandate-aware processing — the same "radicalism" issue is barely relevant to BSSN because most events fall outside the cyber mandate. Conversely, BGN with MBG events 100% in-scope and high velocity escalates straight to War. Polri in a small narcotics case still receives a Positive sentiment because of the success story, but the alert is not inflated due to the low scale. This system refuses one-size-fits-all.
