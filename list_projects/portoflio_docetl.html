What It Does

Turn Questions Into
Data-Driven Answers

A single question triggers a chain of intelligent agents working together to find, validate, extract, and analyze data from thousands of sources.

🔎

Smart Dataset Discovery

Automatically searches through thousands of statistical datasets using semantic understanding — not just keyword matching. Finds the most relevant data even when the question uses different terminology than the source.

⚖

Intelligent Relevance Scoring

Every discovered dataset is evaluated by an AI judge that considers content alignment, geographic coverage, time period match, and data completeness. Only the most relevant data passes through.

📈

Reads spreadsheets from cloud storage, handles multi-sheet files, and uses natural language-to-SQL conversion to pull exactly the data needed — even from files with hundreds of rows and columns.

⚡

Previously answered questions are cached with AI-powered reasoning. When a similar question comes in, the system evaluates if the cached answer is still relevant — saving processing time.

Pipeline Workflow

How It Works

From a simple question to a comprehensive analysis — here's what happens behind the scenes, step by step.

1

You Ask a Question

A user types a question in plain language, such as "Which 5 provinces have the highest village government revenue in 2023?". The question can come from a chat interface, an API call, a queued job, or even a command-line tool.

⚡ Shortcut: If a very similar question was answered before, the system checks its answer cache first. If the cached answer is still relevant (scored by AI), it's returned immediately — skipping all remaining steps.
2

The Question Gets Expanded

An AI agent analyzes the question and breaks it into multiple search terms. For example, "village government revenue 2023" becomes: "realisasi pendapatan desa", "belanja pemerintah desa", "village budget 2023", "APBD desa", and several more variations. Abbreviations are expanded, time periods are calculated, and geographic context is identified.

Abbreviation expansion Time period detection Geographic context
3

Finding Relevant Datasets

Two searches run at the same time: one scans a database of spreadsheet metadata (thousands of government statistical publications), and the other scans a collection of news and web data. The system uses meaning-based search, not just keywords — so it can find relevant data even when the wording doesn't match exactly.

Spreadsheet database News & web database Parallel search
4

Ranking & Filtering Results

Every found dataset is scored from 0 to 100 by an AI judge. The judge evaluates: Does the data cover the right topic? Does it match the requested time period? Does it cover the right geographic area? Only datasets scoring above the quality threshold pass through. A secondary verification model double-checks the rankings.

🔄 Self-Healing: If no datasets pass the quality threshold, the engine automatically lowers the bar and searches again — repeating until it finds usable data or exhausts all options.
5

Extracting the Data

Each qualifying dataset is retrieved from cloud storage. Small files are read directly as spreadsheets. Large or complex files are handled by a text-to-SQL engine that converts the question into a database query, running it against the spreadsheet to extract only the relevant data. Multi-sheet files are automatically split and processed in parallel.

Small files: direct read Large files: text-to-SQL Multi-sheet: auto-split
6

Analyzing & Synthesizing

All extracted data is fed into an intelligent analysis pipeline powered by DocETL — a framework that breaks complex data processing into a chain of specialized operations. The pipeline adapts its strategy based on data size.

🔌 Two strategies: Small datasets are analyzed in a single pass. Large datasets go through a full 4-stage pipeline: the data is split into overlapping pieces, each piece gets surrounding context attached, then each piece is analyzed individually, and finally all analyses are merged into one comprehensive result.
Deep Dive

The Analysis Pipeline

The engine uses a modular pipeline framework where each stage has a specific job. Here's how the pieces fit together:

🗃
Data Source
The prepared spreadsheet data, loaded from a file with the user's question attached
➔
How big is the data?
Small dataset Goes directly to a single analysis step
Large dataset Goes through the full 4-stage pipeline below
1

Split

Divides large data into manageable pieces

When a spreadsheet has thousands of rows, it's too much for a single AI pass. This stage slices the data into overlapping chunks — like reading a book in sections, where each section shares a few pages with the next so nothing falls through the cracks.

Chunk size
~6,500 tokens each
Overlap
~3,500 tokens shared between neighbors
Tracking
Each piece gets a unique ID and sequence number
2

Gather Context

Gives each piece its surrounding context

Before analyzing a piece, the system attaches the piece that comes before it and the piece that comes after it. This way, the AI can see transitions and relationships across boundaries — like reading the paragraph before and after the one you're focusing on.

Context window
1 piece before + 1 piece after
Benefit
No data is lost at chunk boundaries
3

Analyze Each Piece

AI examines every chunk individually

Each piece (with its context) is sent to an AI model for analysis. The model extracts relevant data, identifies patterns, and produces insights specific to that portion of the dataset. All pieces are processed independently — enabling parallel execution.

Per piece output
Analysis summary, relevant data rows, key findings
AI model
Gemini 2.5 Flash or GPT-4o
4

Synthesize Everything

Merges all piece-level analyses into one answer

All individual analyses are combined into a single, comprehensive response. The AI reviews findings from every piece, resolves any contradictions, integrates data tables, and produces the final answer with a clean CSV dataset and a detailed written analysis.

Final output
Integrated CSV table + full markdown analysis
Quality check
Ensures all rows have identical column count
Language
Analysis written in Bahasa Indonesia

How It All Connects

🎭
Pipeline Orchestrator

Ties all stages together into a single execution unit. Defines which data source to use, what operations to run (and in what order), which AI model powers the analysis, and where to write the results.

📋
Execution Plan

A step-by-step recipe that tells the pipeline: "Take the spreadsheet data, run it through Split, then Gather, then Analyze, then Synthesize — in that exact order." Multiple steps can be chained for complex workflows.

💾
Result Storage

The final output is saved as a structured file containing the cleaned data table, the written analysis, column mappings, and processing metadata. Intermediate results from each stage are also saved for debugging.

Pipeline Variants Used in Production

Question-Answering Pipeline

The primary pipeline. Takes the user's question and extracted data, then generates a direct answer with supporting tables and analysis.

Used by: Main statistical analysis engine
Table Normalization Pipeline

Focuses on cleaning messy spreadsheets: detecting headers, standardizing column counts, fixing formatting issues, and producing a clean, consistent table.

Used by: Data normalization & scanning workflows
Correlation Analysis Pipeline

Examines relationships between two variables (e.g., crime rate vs poverty level). Identifies patterns, geographic variations, and produces strategic recommendations.

Used by: Cross-document analytics & POLRI insight engine
7

Delivering the Results

The final analysis is sent back to the user as a formatted response. Simultaneously, the system saves the cleaned data to cloud storage (as spreadsheet and CSV), adds it to the answer cache for future queries, indexes it for searchability, and logs the entire process for monitoring.

User response Cloud storage Answer cache Event log
Core Components

The AI Agents

Eight specialized agents, each with a focused role. They work together like a team of analysts — one breaks down the question, another finds data, another judges quality, and so on.

🔎
Question Analyzer
Understands what you're really asking
Takes your question and breaks it into multiple precise search terms. Expands abbreviations (e.g., "Tangsel" becomes "Tangerang Selatan"), identifies time periods, and generates broader variants to ensure nothing is missed.
receivesYour question in natural language
produces3 to 8 expanded search terms
⚖
Relevance Judge
Scores how well each dataset matches
Reviews every discovered dataset and assigns a relevance score from 0 to 100. Checks if the data covers the right topic, time period, and geographic area. Ensures no duplicate datasets pass through.
receivesYour question + list of found datasets
producesScore, reasoning, and pass/fail for each
📅
Time Period Detector
Extracts date ranges from descriptions
Reads dataset descriptions and identifies what time period the data covers. Understands Indonesian month names, year ranges, and can determine if a dataset is about a single year or spans multiple years.
receivesDataset title and description
producesDate range (e.g., "2020 – 2024")
✅
Data Validator
Confirms data actually answers the question
A final check before data enters the analysis pipeline. Verifies that the content of each dataset genuinely matches what the question asks for — catching false positives from the search phase.
receivesYour question + dataset content preview
producesValidation result with confidence
🧠
Cache Evaluator
Decides if a previous answer can be reused
When a similar question has been answered before, this agent evaluates whether the cached answer is still good enough. It considers how closely the new question matches the old one and whether the data might be outdated.
receivesNew question + cached answer candidates
producesReuse recommendation with confidence score
📊
Chart Designer
Creates visualizations from data
Analyzes the extracted data and determines the best chart type (bar, line, pie, etc.). Generates a complete chart configuration including colors, labels, and tooltips. Uses a specially trained model for optimal visualizations.
receivesExtracted data in table format
producesReady-to-render chart configuration
📝
Table Formatter
Makes raw data presentable
Takes raw spreadsheet data and converts it into clean, readable tables. Handles messy headers, inconsistent formatting, and missing values to produce well-structured output ready for analysis.
receivesRaw spreadsheet data
producesClean, formatted data table
⚙
Foundation Layer
Powers all other agents
The shared infrastructure that every agent builds on. Provides reliable communication with AI models, automatic retries when things go wrong, and detailed logging of every operation for monitoring and debugging.
receivesInstructions from any specialized agent
producesAI response + performance metrics + event log
