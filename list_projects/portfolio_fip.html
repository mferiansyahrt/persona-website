Tantangan Integrasi Data

1 Heterogenitas Format Geometri

Hotspot adalah POINT, konsesi POLYGON, simulasi rambatan MULTIPOINT, gambut MULTIPOLYGON. Semua harus disatukan via PostGIS — ST_Within untuk attribusi, ST_Union untuk agregasi, ST_AsGeoJSON untuk serialisasi.

hotspot → POINT(lon lat) konsesi → POLYGON gambut → MULTIPOLYGON rambatan → MULTIPOINT (per time_hour)

2 Multi-Row per Kombo

Tabel silver.fire_spread_riau menyimpan banyak baris per (hotspot_id, time_hour). Untuk render 1 MultiPoint utuh, query pakai CTE + ST_Union ber-GROUP BY.

WITH spread_agg AS ( SELECT hotspot_id, time_hour, ST_AsGeoJSON(ST_Union(geometry)) FROM silver.fire_spread_riau GROUP BY hotspot_id, time_hour )

3 Sinkronisasi Time Window

Filter PERIODE di dashboard (Hari ini, 7 hari, 30 hari, custom range) harus konsisten di semua endpoint. Helper _normalize_date_range sentralisasi konversi days ↔ date_from/date_to dengan clamp lookback & swap reversed.

4 LEFT JOIN Bocor ke UI

Hotspot tanpa data simulasi tetap return dari LEFT JOIN dengan frames=[]. Tanpa filter Python, selektor FE tampil “HOTSPOT AKTIF 1/1” padahal peta kosong. Solusi: post-filter [h for h in groups.values() if h.get("frames")].

5 Cache-Aside Multi-Tier

TTL berbeda per endpoint sesuai tingkat freshness: hotspot 5 menit (data live), cluster 30 menit, news 15 menit, peat overlay 24 jam (statis). Cache key di-versioning per filter signature.

6 Snake_case Bocor ke Layar

String yang di-feed LLM mengandung enum mentah seperti lulc_plantation, night_burn_flag. Dipakai mapping _POLYGON_TYPE_ID & _INDICATOR_LABEL_ID di engine untuk humanisasi sebelum render.

Alur Pembangunan
Dari satelit ke layar operator
Pipeline cache-aside tujuh lapis. Setiap lapisan punya tanggung jawab tunggal dan dapat di-trace via log + Redis introspection.

Arsitektur Berlapis

1 Ingest — Sumber Eksternal

Hotspot BMKG, cuaca NASA POWER, konsesi sawit dari Kemendagri, polygon gambut WDPA, dan scraper berita karhutla. Masing-masing punya frekuensi refresh berbeda: hotspot 3-6 jam, cuaca harian, konsesi/gambut statis, berita kontinu.

2 Store — Bronze & Silver Layer

PostgreSQL dengan tiga cluster terpisah per domain (Kementan, Kemendagri, POI). Schema bronze.* menampung data mentah, silver.* menampung agregat dan geometri yang sudah diolah dengan indeks GiST untuk spatial join cepat.

3 Compute — Analytical Engines

Enam engine berlapis: DBSCAN clusterer, cause rule engine, intent classifier, temporal stats, spatial assignment, cellular automata fire spread. Semua deterministik — hasil dapat diaudit dan reprodusibel.

4 Enrich — Bukti Berita & Cuaca

NewsEvidenceService mencari artikel relevan per cluster lewat geo_distance Elasticsearch. WeatherEvidenceService inject konteks cuaca (kekeringan ekstrem, presipitasi rendah, periode kemarau anomali) untuk grounding narasi LLM.

5 LLM Synthesis — Agent Layer (optional)

Cluster Intel Agent untuk narasi historis, Prediksi Briefing Agent untuk tactical briefing per zona. Semaphore-gated (max 3 concurrent), timeout 90s. Selalu ada fallback template deterministik — respons tidak pernah HTTP 500.

6 Cache & Serve — Redis + FastAPI

Multi-tier TTL per endpoint (hotspot 5 m, cluster 30 m, news 15 m, peat 24 j). Cache key versioned per filter signature. ResponseEnvelope JSON dengan meta info untuk transparansi state ke frontend.

7 Render — Frontend Layer

Zustand store sebagai single source of truth, Mapbox GL render geometri (layers, sources, paint), React komponen untuk panel intelijen, chart ECharts untuk timeline historis-prediksi. URL sync untuk shareable view.

Cara Pembangunan — Fase per Fase

1

Discovery & Schema Reconnaissance

Verifikasi struktur tabel database sebelum coding: tipe kolom, granularity, distribusi nilai. Banyak bug awalnya muncul karena asumsi salah (mis. time_hour varchar “T+1” bukan integer). Setiap penambahan endpoint diawali query sample data.

2

Backend Endpoint & SQL First

Tulis SQL dengan CTE + ST_Union + BETWEEN date_from AND date_to, test langsung di DB dulu. Validasi performa (worst-case 90-day query ≤ 300 ms) sebelum dipanggil dari FastAPI router.

3

Pydantic Schema & ResponseEnvelope

Definisikan DTO Pydantic untuk request & response — FastAPI auto-generate OpenAPI. Bungkus dalam ResponseEnvelope standar dengan meta info (stale flag, generated_at, total count).

4

Frontend Service Layer (realApi)

Modul realApi.ts mengisolasi semua HTTP call ke satu tempat. Setiap fungsi terima opts object & signal abort. Mock mode disediakan untuk dev tanpa BE — toggle via VITE_USE_REAL_API.

5

Zustand Store dengan Cache Signature

Store memegang data + loading flag + cache signature per filter window. Re-fetch saat signature berubah, skip kalau sama. Reset animation pointer otomatis ketika list ter-update supaya idx tidak out-of-bounds.

6

Mapbox Layer Setup di MapController

Pola epoch-based: setup source + layer sekali per mapStyleEpoch, useEffect kedua update setData berdasarkan state animasi. Layer visibility di-toggle via setLayoutProperty('visibility').

7

QC Iterasi & Polishing

Setiap fitur diuji dengan QC checklist: istilah teknis Indonesia, penanganan empty state, dynamic positioning panel terhadap sidebar, zoom-responsive sizing, tooltip non-popup. Bug deployment dipisah dari bug kode.

Komponen UI Khas

A Map-First Layout dengan Vertical Tab

Peta full-screen di z-index 0. Vertical tab kiri (Filter & Layer) dan kanan (Daftar Zona Rawan) dengan slide-in panel. Hover untuk preview, klik untuk pin. Memberi ruang map maksimal saat panel tertutup.

B Dynamic Positioning Antar Panel

Detail Zona Card auto-shift ke kiri ketika Daftar Zona Rawan terbuka. Fire Spread Controls juga geser otomatis berdasar 4 state visibility supaya tidak saling tertimpa.

C Animasi Cumulative Frame

Simulasi rambatan api render cumulative — frame T+6 menampilkan gabungan T+1 + T+6, T+12 menambahkan T+12, dst. Loop tak berhenti dengan delay 1200 ms per frame, bisa di-pause manual atau via klik bullet timeline.

D News Ticker Inline di Filter Bar

Running text berita karhutla di-inline di FilterBar (basis-full line break) sehingga tidak menyita baris tersendiri saat viewport lebar. Marquee speed proporsional terhadap panjang konten supaya konsisten visual.
