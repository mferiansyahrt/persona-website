What It Does

From a Vague Request to Cited Answers

This is not a chatbot answering from memory — it actively finds real documents on the open web, reads them, and answers strictly from what those documents say.

🔍
Search & Discover

A single user request is expanded into multiple Google-style PDF queries by the Query Variator, each fired through SerpAPI in parallel. Optional URL normalization converts academic links (arXiv, bioRxiv, PMC) into direct PDF downloads.

📄
Verify & Extract

A verification agent scores every candidate link 0–100 and filters out non-downloadable URLs. Surviving PDFs are downloaded concurrently with SSL fallback and dual extractors (PyPDF2 → pdfplumber), with smart page-centering to skip covers and tables of contents.

🧠
Analyze & Answer

Each page is scored for relevance and deeply analyzed in parallel. A Q&A agent consolidates every insight into one grounded answer in Bahasa Indonesia. In full mode, documents are pushed to S3 + Kafka for a downstream knowledge base.

Relevance Scoring Engine

Every Document Earns Its Place

Both links and page content are scored 0–100 by dedicated agents. Thresholds act as quality gates — weak matches are filtered out, only strong matches are ingested into the knowledge base.

Filtered Out
Score ≤ 30
Non-downloadable links or content with weak/no connection to the query. Dropped early so downstream agents never waste compute on irrelevant material.
Relevant
Score 31–69
Passes the verification gate and proceeds to download, extraction, and per-page deep analysis. Contributes to the synthesized Q&A answer.
Knowledge-Grade
Avg Score ≥ 55
High-confidence sources. In full-document mode these are uploaded to S3 as structured "docling" JSON and produced to Kafka for the downstream knowledge base.
How It Works

From User Query to Grounded Answer

The pipeline runs in two coordinated phases: a fast interactive answer is returned immediately, while full-document extraction continues in the background. Conditional branches skip unnecessary work to save LLM calls.

1
Query Variation
The Query Variator agent converts one analytical request into num_docs targeted, Google-ready PDF queries in the form "Dokumen pdf mengenai …" — expanding coverage through synonyms, scope shifts, and site hints (e.g. arXiv).
QueryVariatorgpt-4o-mini1 → N queries
2
Parallel Web Search (SerpAPI)
Each query variant is dispatched as its own gather_pdf task and run concurrently via asyncio.gather. SerpAPI queries Google (location=Indonesia, hl=id), and results are restructured into clean link + title + snippet records.
SerpAPIasyncio fan-out
3
URL Normalization (Optional)
When enabled, the URL Manipulator agent rewrites academic landing pages into direct PDF URLs — e.g. arxiv.org/abs/ID → arxiv.org/pdf/ID.pdf — while leaving already-downloadable and non-academic links untouched.
UrlManipulatorAgentarXiv / bioRxiv / PMC
4
Link Verification & Scoring
The PDF Verification agent inspects every candidate, keeping only links that end in .pdf or contain "download", and assigns each a 0–100 relevance score with reasoning. Links scoring above the threshold pass; the rest are dropped.
PDFVerificationAgentScore gate > 30
5
Branch: Search-Only Fast Path
If search_only=True, the engine returns verified links with titles & snippets immediately — an instant, low-latency result set — while the full extraction continues in the background phase.
Instant resultsNo download
6
Concurrent PDF Download & Extraction
Verified PDFs are fetched in parallel with an SSL-verified attempt and an automatic no-verify fallback. Extraction uses PyPDF2 first, then pdfplumber on failure. Pages are read in batches inside a thread pool so the event loop never blocks, with timeouts guarding every stage.
aiohttp + SSL fallbackPyPDF2 → pdfplumberThreadPoolExecutor
For every extracted page, these 2 analyses run in parallel
Relevancy Analyzer

Scores how well the page content answers the query (0–100) with structured reasoning — the signal used for ranking and the average-score gate.

Deep Analysis

Produces a rich, strictly source-grounded markdown analysis (executive summary, in-depth findings, implications) used to compose the final answer.

7
Page-Centering Optimization
In fast mode the reader doesn't blindly take pages 8–15 — it centers extraction around 40% of the document, where the substantive content typically lives, skipping covers, prefaces, and tables of contents to maximize signal per token.
Smart page selectionToken efficiency
8
Score Aggregation & Ranking
Per-page relevance scores are averaged into an avg_score per document, and deep-analysis sections are concatenated into one consolidated insight stream per source — producing a ranked, evidence-rich view of every PDF.
avg_scoreConsolidated insight
9
Answer Synthesis (Q&A)
In fast mode, the PDF Q&A agent consolidates every document's insight — merging duplicates, cross-referencing sections — into one coherent, grounded answer to the original question, written in professional Bahasa Indonesia.
PDFQnAGrounded synthesis
Background phase (full-document mode) — runs asynchronously via Redis
Full Extraction

The Redis worker re-runs the pipeline with all_pages=True, extracting every page of each knowledge-grade PDF.

S3 Upload

Each document's full text + insight ("docling" JSON) is written to S3 (MinIO) and assigned a stable URL.

Kafka Production

A document record (title, URL, domain, S3 path) is produced to the knowledge-pdf topic for downstream ingestion.

✓
Delivery: Instant Answer + Durable Knowledge
The user receives a grounded answer (or verified link set) in seconds, while a reliable Redis queue (brpoplpush + worker semaphore) guarantees the full-document knowledge is extracted, stored, and broadcast — observability for every LLM call is streamed to Kafka log topics throughout.
Fast responseReliable queuePer-call Kafka logging
